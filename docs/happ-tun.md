# Happ: режим TUN не исполняет профиль маршрутизации

Коротко: **людям на Xray нужен режим «Прокси», а не TUN.** В TUN приложение
берёт из профиля только прямые списки, туннельные игнорирует целиком и
отправляет весь несовпавший трафик мимо туннеля. Со стороны это выглядит как
«VPN не работает»: российские сайты открываются, заграница нет.

Проверено 18 сентября 2026 на Happ 4.2.1 (608), ядро Xray 26.7.28, Windows,
`tunProvider: xray`.

## Что происходит

Профиль доезжает и применяется — приложение само пишет об этом при подключении:

```
[ROUTING]: Pre-flight check: using routing profile 'Сплит от бота'
[TUN]: xray TUN interface up
[TUN]: Tun mode enabled
```

Прямые правила из профиля исполняются:

```
tcp:203.0.113.10:23232  → direct    из DirectIp
tcp:www.gosuslugi.ru:443   → direct    из DirectSites
```

А туннельные — ни одно:

```
udp:10.13.13.1:53          → direct    хотя 10.13.13.0/24 стоит в ProxyIp
tcp:kws2.web.telegram.org  → direct    хотя regexp:.* стоял в ProxySites
tcp:mtalk.google.com:443   → direct    хотя 0.0.0.0/0 стоит в ProxyIp
taking detour [proxy]        0 раз
```

Домен, не совпавший ни с одним правилом, уходит напрямую — значит выходом по
умолчанию стоит прямой, хотя в профиле `GlobalProxy: true`.

## Почему это ломает всё, а не только маршрутизацию

`RemoteDNSIP` у нас — резолвер узла, `10.13.13.1`. Он достижим только через
туннель. Запрос к нему уходит напрямую, ответа не получает никогда:

```
app/dns: failed to lookup ip for domain ... at server UDP:10.13.13.1:53
         > record not found
```

Ни одно имя не разрешается. Без разобранного имени приложение отправляет
напрямую вообще всё. Российские сайты при этом открываются — они и так
доступны, — а заграница нет.

## Что пробовали со своей стороны

Ничего из этого не помогло, и это не догадки — каждое проверено на живом узле с
живым ключом:

| Что сделали | Версия | Итог |
| --- | --- | --- |
| Вырезали сеть узла из `DirectIp` (её накрывала `10.0.0.0/8`) | 8.38.0 | правило по сетям в TUN не применяется |
| Добавили `LastUpdated`, чтобы профиль вообще обновлялся | 8.39.0 | **помогло**, профиль доезжает |
| Ноль-сеть `0.0.0.0/0` в `ProxyIp` | 8.44.0 | не применяется |
| Адрес узла в `DirectIp` первой строкой | 8.44.1 | **работает** — прямые списки исполняются |
| `regexp:.*` в `ProxySites` | 8.45.0 | не применяется, правило убрано обратно |

Вывод: со стороны профиля это не чинится. Профиль составлен по документации
приложения — в её собственных примерах `GlobalProxy: true` стоит вместе с
непустыми `ProxyIp`/`ProxySites`, и сказано, что несовпавший трафик идёт в выход
по умолчанию.

## Что делать людям

**Режим «Прокси».** Там приложение собирает конфиг, где туннель стоит выходом по
умолчанию, и всё работает — проверено. Оговорка одна: в туннель пойдут только
программы, уважающие системный прокси. Браузер и мессенджеры пойдут, часть игр
и клиентов — нет.

Если понадобится TUN — вопрос к автору приложения; выше лежит всё, что нужно
приложить к обращению.

## Что можно проверить у себя

В отчёте приложения (`Настройки → Отчёт`):

- `report/routing.json` — какой профиль применён и что в нём;
- `report/core_log.txt` — строки `taking detour [...]`. Если `proxy` там ноль, а
  `direct` десятки, трафик мимо туннеля;
- `report/settings.json` — `AdvancedSettings.tun` показывает режим.
